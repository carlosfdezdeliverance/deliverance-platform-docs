    Referencia de API: Introducción¶

    ¿Qué es una API REST?¶

    Una API REST es una forma estándar de que un programa hable con otro por internet: en vez de abrir el navegador y hacer clic en botones, un programa envía una petición HTTP a una dirección concreta (endpoint) y recibe una respuesta, normalmente en formato JSON. Cada endpoint tiene un método (GET para leer, POST para crear, PUT/PATCH para modificar, DELETE para borrar) y una ruta (por ejemplo /api/v1/devices/).

    ¿Para qué sirve la API de Deliverance?¶

    Da acceso por código a todo lo que se puede ver y hacer desde el Dashboard: dispositivos, tareas, organizaciones, usuarios, escenas y sus métricas, sin tener que usar la interfaz web. Sirve para integrar los datos de la plataforma en otro sistema, automatizar acciones, o construir herramientas propias encima de los mismos datos que usa el Dashboard.

    Categorías (tags)¶

    Los endpoints se agrupan por categoría. Cada una tiene su propia página en este manual:

    Categoría Contenido
    login Autenticación: obtener y verificar el token de acceso.
    users Gestión de usuarios.
    utils Utilidades internas (health check, email de prueba).
    devices Dispositivos, su estado, tareas, alarmas y lecturas IoT.
    tasks Tareas ejecutadas por los robots.
    organizations Organizaciones, su jerarquía, métricas e informes.
    scenes Escenas/mapas asociados a una organización.
    private Endpoints de uso interno.

    Campos y patrones básicos que vas a encontrar en casi cualquier endpoint¶

    • 🔒 Autenticación: casi todos los endpoints requieren un token. Se consigue haciendo login (ver login) y se envía en la cabecera Authorization: Bearer <token> en cada petición siguiente.
    • uid / id: identificador único de cada recurso (dispositivo, tarea, organización, usuario...). Es un UUID, no un número correlativo.
    • Fechas y horas: siempre en formato ISO 8601 (por ejemplo 2026-07-28T00:55:47.387340).
    • Listados: los endpoints que devuelven varios elementos (GET /devices/, GET /tasks/, etc.) no devuelven un array suelto, devuelven un objeto con esta forma: 
      { "data": [ ... ], "count": 12 }
      count es el total de elementos disponibles, no el número de elementos en data (útil para paginación).
    • Paginación: los listados aceptan skip (cuántos saltarse) y limit (cuántos devolver como máximo).
    • Campos "libres": algunos campos (category, status, type...) son texto libre a nivel de API, sin una lista cerrada de valores impuesta por el servidor. Los valores reales que existen se explican en la página de cada categoría, donde aplique.
